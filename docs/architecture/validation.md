# Validation

The chief architect merged the proposals into [plan-draft.md](plan-draft.md). Four validators attacked the draft, and an editor applied the findings that held to produce [the final plan](../plan.md).

## Synthesis summary

Plan written to /private/tmp/claude-501/-Users-svidskiy-Developer-svidskiy-dawnfolk/f224a3c7-cf6b-4066-884d-19a8c99c1ec2/scratchpad/architecture/plan-draft.md. It is about 1,500 lines and has all 15 sections. I didn't publish it anywhere or touch the repo.

**Base: evolve.** It had the top critic mean (5.2, vs 5.0 for ecs and 4.8 for packages) and the best determinism and save scores. It keeps today's typed-array stores, so it needs no ECS rewrite. Its weak spots were migration (4) and simplicity (5), so most grafts go there.
- **Structure:** four layers plus modules: `core/{foundation,catalog,world,protocol}`, `simulation/{kernel,state,queries,rules,api,generation,nature,life,runtime}`, `engine/{bridge,mirror,models,render,audio,input}`, `interface/{design,stores,panels,pages,app}`, `assembly/`, and `modules/<id>/{module.ts,messages.ts,shared,simulation,engine,interface}`. Paths are at most 4 folders deep.
- **Enforcement:** five composite tsconfig projects (core, simulation, engine, interface, tests). A Bun script, `bun run boundaries`, checks layer imports, which modules may use each other, and that nothing the worker loads reaches three, React or zustand. A Biome GritQL rule enforces exact math in deterministic code. There are no workspaces.

**Grafts**
- **From ecs:** one compiled kind table with a value array per property; a generation number per plant slot; event-driven responses; every structure either saved or derived.
- **From packages:** a throwaway spike first; one ordered system list pinned by a test; generic catalog events with a `cause`; the worker-closure check; exposures merged into fields as `lifetime: "tick"`.
- **From the critics:**
  - Typed handles (`defineField`, `defineTag` and the rest) instead of closed name unions, plus an assembly layer that owns the module list and the event and frame key types.
  - Field storage tiers with two write paths: owning kernels write raw arrays, everyone else goes through one shared writer.
  - Reactions run as batch kernels; dense fields can't drive them.
  - `ThingSource` adapters over today's stores, plus a new store for tornadoes, meteors and other short-lived things. People and animals stay objects.
  - `Surroundings` with prepared area queries, `tally`, cell filters, discs, capsules and regions, a fixed tie order and no side effects.
  - `strike(Blow)` with harm, push, swirl and uproot.
  - A step counter separate from the game-time tick; a `TickSource` interface; quantized commands.
  - Extension points for tribes and fauna: a job registry with bands, extra columns, stats with modifiers, relations, animal brains.
  - Lossless WorldBase, numeric bench gates, and each file moving once via `moves.json` and `apply-moves`.
  - A read-only Surroundings facade early, and the tornado as the pilot module.

**High findings and how each is handled**
- **Iteration order changes between live and loaded worlds:** active sets become bitsets scanned in ascending order; plant lists stay sorted; free lists are saved; indexes refresh only at phase boundaries.
- **Save churn from memory changes:** saves get one logical schema designed once, plus one frozen reader for today's version-1 saves that is never extended. Format changes go old-and-new-keys-first, then drop the old. Unknown sections are kept verbatim. A load with losses is never autosaved over.
- **WorldBase was lossy and too big:** row delta, byte shuffle and gzip measured 5.7 MB against 16 MB raw. It goes in its own IndexedDB database, `ashfolk-bases`, so the saves database needs no version bump. Generation-changing PRs wait until it ships.
- **Reactions too slow (closures per cell):** batch kernels resolved at creation; dense drivers are rejected; dense rules run on a row sweep.
- **Hashing cost:** the hasher keeps its own dirty bits and hashes only for lockstep, replays, tests or debug, once per turn.
- **Lockstep timing at high speed:** turns are 100–200 ms of real time holding `speed` ticks; pause is a command, speed is scheduler state; brush strokes are per-step samples.
- **Query cost at tornado radii:** bucket and cell-scan costs are stated honestly (5–25 µs at 45–140 m). Block counts are added only if a bench needs them.
- **Closed unions blocked extension:** replaced by typed handles. Filters resolve per world inside `create`, never at module scope.
- **Moves breaking main and in-flight branches:**
  - First an in-place untangle (M1), then moves folder by folder straight to final paths.
  - The move script also rewrites the 118 `new URL` literals.
  - The same PR updates ship.js, biome, vite, AGENTS.md and the docs, and a guard test fails if an old folder reappears.
  - Moves merge in empty windows; the plan also asks the owner for a merge queue.
- **Hash-neutral claims weren't verifiable:**
  - CI compares canonical digests between the merge base and the PR head; a hash change needs a `Hash-Change:` trailer and gets logged.
  - G3 (now K2) keeps today's exact system order.
  - R1 puts module systems at their final slots, so later extraction stays hash-neutral.
  - The strike work starts as a facade over today's calls.
- **Does release batching apply? No.** Every merge deploys, so batching isn't possible. Simulation-only hash changes don't break saves; only generation changes are gated.
- **Effort was underestimated:** re-estimated at 100–130 PRs, 50–70k changed lines, 8–12 weeks. Lingui is replaced by typed message tables, and zod/mini is its own step (I3). The server/ and e2e/ renames are dropped.

**Packages**
- **Remove:** comlink, react-markdown, remark-gfm.
- **Switch:** zod to zod/mini.
- **Add (dev):** fast-check; ts-morph only while the moves run.
- **Rejected:** dependency-cruiser and swc, since all imports are relative and a Bun script covers it; also ECS libraries, spatial-index libraries, workspaces and Lingui.

### Findings

- **high** · Target structure / How it is enforced, item 2 (bun run boundaries): The draft says Bun.Transpiler.scanImports plus path resolution 'gives the full graph, new URL(…, import.meta.url) included'. That is false in two ways. scanImports drops every `import type` statement, because the TS loader erases them. It also never reports new URL(…, import.meta.url) references. A script built as described would miss most of the cross-layer edges the layer table is meant to catch, so the goal 'a boundaries check that fails on a wrong import' would silently pass.
  - Evidence: I ran architecture/validator/scan.ts on Bun 1.4.4. For the input `import type {B} from './b.ts'; new Worker(new URL('./worker.ts', import.meta.url)); new URL('./sound.webm', import.meta.url)`, scanImports returned only the value import, the dynamic import and './p.md?raw'. The type import and both new URL edges were missing. $R/src has 918 non-test `import type` statements out of about 3,273 relative imports. 88 of the 88 main-thread→simulation imports that use `import type` would be invisible, for example $R/src/rendering/agents/people-view.ts:3 (`import type { GroundPoint } from "../../game/camera/god-camera.ts"`) and $R/src/features/rivalry/*.tsx (RelationView). The worker entry and 117 sound URLs are reached only through new URL ($R/src/game/simulation-connection.ts:42, $R/src/audio/sound-catalog.ts).
  - Fix: Say that the script parses the source itself. Options: the TypeScript compiler API in a scan that keeps type imports (ts.preProcessFile also reports type-only imports), or Bun.Transpiler with loader 'tsx' plus a regex pass for `import type`/`export type … from` and for `new URL("…", import.meta.url)`. Strip `?raw` and other query suffixes before resolving. Keep scanImports only for the worker-reachability check, where type imports really are erased. Add a test that a planted type-only import and a planted new URL edge both get reported.

## Validator: redteam

The direction holds up: typed-array fields, a store-agnostic query API, catalog handles, save sections and lockstep-ready commands are the right base. The plan cannot be carried out as written, though. I found 4 high, 12 medium and 6 low findings, each checked against the code in $R or measured.

The four high findings:
- **Paused steps.** The plan's own `runStep` returns before it drains events or refreshes indexes, so a save taken while paused loses the queued events.
- **Sliced rebuilds against "derived state".** Hydrology and navigation are rebuilt in slices, yet the plan treats them as derived and rebuilds them in full after a load. A save taken mid-slice therefore breaks `save, load, run N` and lockstep resync. Today's code already does this, with a 50-tick navigation check against an immediate rebuild on restore.
- **Hash budget.** The 0.3 ms per turn budget fails by about 4 to 6 times whenever it rains at speed 16 or higher. Measured cost is 7.9 µs per 64×64 chunk of one f32 field, and the surface sweep rewrites wetness on every land cell.
- **Acid-rain walkthrough.** "Core edits: none" is false. Core code indexes static arrays built from the base content, so a ground added by a module writes NaN into fuel.

The medium findings cover the rest:
- Plant indices break once one kind table spans every group.
- D2 quietly changes generation and the pond outlines that saved worlds redraw at runtime.
- Unknown rows that are "kept verbatim" collide with reused plant slots and building cells.
- Q2 cannot be hash-neutral with a row-major iterator.
- Several migration lanes depend on later steps: Q3, R3 and X need R6; S4 needs T1; E1 needs K4.
- Shared hazard code (`explode`, `shakeLand`) has no home under `requires`.
- `core/protocol` and `assembly` would import each other at the type level.
- Cell properties are closure chains that look up fields by handle on every call.
- Navigation rebuilds every tick once ice counts as walkable.
- Meteor timing, brush strokes as per-step commands, the incremental hash, and WorldBase writes across two databases each have a gap.

Fix the high findings and the lane order before phases K, Q and R begin.

Exposures such as `soak` last only one tick, so a sample that applies N ms in one step saturates `min(1, soak * seconds)`. Douse strength then depends on frame rate and speed.

  - Evidence: Plan lines 788-790 ('digest of a section is a canonical hash of its `write` output ... - **medium** · Determinism > Saves > WorldBase: The base lives in its own database, `ashfolk-bases`, so a save and its base can never be written in one transaction.   - Evidence: Plan lines 1061-1066: written 'in the worker after the world appears', 'its own IndexedDB database', 'Orphan bases are deleted when no save references them'; compression takes 16 MB down to 5.7 MB. ## Validator: completeness

Not ready to adopt. The draft resolves most performance and identity findings: batch reaction kernels, no dense drivers, numeric budgets, hashing only when something consumes it, one frame per advance, generational plant slots, name tables, lossless WorldBase, and no lazy index built by a query. It does not fully resolve the layer-graph and extensibility findings. The handles everything depends on (traits, fields, kinds) are defined on simulation sides, yet the engine, module.ts and the main-thread Surroundings need them. core/protocol still needs types that are composed in assembly. Scenarios and goals, a Next roadmap item, are deferred outright. The save rule "designed once, never changes meaning" is broken in three places in the draft itself (health, lava, expand–contract). Two mechanisms the migration relies on also fail against the repository as it is. D2's "simulation first" exact-math batch changes generated worlds through code that generation and the runtime share. The merge queue the plan relies on is unavailable to this user-owned repository, and CI can neither run it nor commit fixtures. Coverage gaps: composition roots for the engine and interface module sides, the Cloudflare worker and server side, PWA update behavior, testing helpers and other unplaced files, ship gates and reviewer rules, a replay step before Phase L, crossings and deposits as queryable things, and several lane-order errors (S4 needs T1, X needs Q3/R5/R6, Q is gated behind the moves for no reason).
